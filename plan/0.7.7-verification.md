# 0.7.7 — what was exercised, and what it answered

Run on 2026-10-25 against the minikube install (image built from
`release/0.7`, server reporting 0.7.6 because the version is not bumped yet),
through the same endpoints the pages call, with an admin session. The scripts
are in the session scratchpad; this is what they found.

Three faults came out of it, all fixed on the branch: bug-044 (the last
order-dependent test), bug-046 and bug-047. Two of the three were invisible
to the suite because the tests read the database rather than the answer.

The backend suite had failed in a full run and passed in every subset since
the alerts fix; that was bug-044, and it is named now.

**`pnpm` does not run on this host any more.** node was upgraded to 26.10.0,
`package.json` pins `>=18 <26`, and `/opt/homebrew/bin/pnpm` is a corepack
symlink into the removed `Cellar/node/24.4.0`. The four checks above were run
with `node node_modules/typescript/bin/tsc` and `node
node_modules/jest/bin/jest.js` directly. CI installs node 24 and pnpm
10.30.3 itself, so CI is unaffected; a local `pnpm install` is what needs
node 24 back.

## Reads: every endpoint a page loads

44 endpoints, all 200, shapes checked rather than status alone: session,
config, home summary, organization status and settings, data sources and
their types, queries (list, mine, recent, favourites, archive, tags),
dashboards (list, mine, favourites, tags, folders), alerts, destinations and
their types, snippets, users, groups, events, streams and running streams,
catalog (tables, sources, measures, queries, score), MCP (mine, audit),
OAuth tokens, and the admin pages (overview, outdated queries, running
queries, RQ status, storage, OAuth tokens).

`GET` on `/api/widgets`, `/api/visualizations` and `/api/mcp` answers the SPA
to a signed-in browser and 404 to anything else: those routes are POST-only,
so a client that tries `GET /api/mcp` looking for an SSE stream gets a clean
404 and falls back to POST. Nothing to fix.

## Queries

- Connection test on the cluster Postgres: `{"ok": true}`. Schema: 35 tables.
- Create, run, read the result, and all three downloads — csv (26 bytes),
  xlsx (5 kB, real Excel 2007+ container), json.
- The formatter, search, tags, and the version history: two versions after
  one edit, each attributed.
- Edit through the API: name, description and a daily schedule.
- A parameterised query run with `{"n": 7}` executed `SELECT 7::int AS n` and
  returned `[{"n": 7}]`. `latest_query_data_id` stays null for a
  parameterised run, which is right — the cache is keyed by the values.
- A query against a table that does not exist failed with the database's own
  message and no credential in it.
- Fork, favourite (and the favourites list), and regenerate API key — **the
  last of which is bug-046**: the response came back without the key.

## Catalog, which is what MCP reads as context

- 44 tables with usage counts; `harvest` queued all four sources.
- An admin editing a table's own words is recorded as
  `description_source: human` with `described_by` and `described_at`.
- Measures: listed with kind, column and usage count; edited; a proposal
  denied as a curator would deny it. Measures are created through MCP's
  `propose_measure`, not through REST — `/api/catalog/measures` is read-only
  by design.
- `GET /api/catalog/export` returns a zip of one YAML per table.
- `GET /api/catalog/score` is `null` until somebody points
  `SQLDESK_CATALOG_EVAL_FILE` at a questions file. Documented, deliberate.

## Streams

- Six topics on the local Redpanda. `analyse` on `orders` read 500 messages,
  found JSON, inferred four columns, and reported 0.92 events/second against
  a 1800-second window and a 200k row budget.
- `stream_schema` refuses JSON with "Only Avro and Protobuf take a schema
  file."
- Starting a watch consumed 28 rows in 20 seconds; a 60-second window
  aggregated by region correctly; slots were accounted (1 of 5 used, 2 per
  user); stopping worked.
- A window over a topic nobody is consuming returns zero rows. That is the
  contract, not a fault: start the stream first.

## MCP — all thirteen tools

`initialize` and `tools/list` answer; the 13 tools advertise their schemas.

| Tool | Answered with |
| --- | --- |
| `list_data_sources` | four sources with dialects and descriptions |
| `find_context` | the catalog for the question, with a staleness warning naming the sources and the age |
| `find_queries` | query, owner, dates, and each visualization's own description |
| `find_dashboards` | dashboard, widget count, owner, and every widget with its source query |
| `find_measures` | expression, description, provenance (also sent `structuredContent` then; removed 2026-10-25) |
| `expand_table` | the table in both data sources that hold it, with columns and the human description |
| `check_sql` | dialect, and warnings for a missing WHERE/LIMIT and for `SELECT *` |
| `explain_query` | the real Postgres plan |
| `run_query` | `queries / 133` |
| `save_query` | draft 579, with the message saying it stays a draft until published |
| `update_query` | the change as before → after |
| `propose_measure` | proposed, and that it reaches nobody until a curator agrees |
| `update_table` | `Described orders.` |

Refusals are all clear and all audited: `DELETE` as a query → "That statement
contains DELETE; only reads can be run from here."; an unknown table → "None
of those tables are in the catalog."; an ambiguous table name → "'orders' is
in 2 data sources (Demo stream, Redpanda Local Streams). Say which with
`data_source`."

The audit trail holds 124 events, refusals included, with before → after text
for `update_table` and `update_query`.

## Left as it is

- **The "Demo stream" data source is unreachable** — it points at
  `host.minikube.internal:15433` and nothing is listening there. MCP can
  describe `orders` but not query it, so the demo needs that Postgres back up
  before anyone shows it. Not a product fault.
- An unauthenticated POST to an API endpoint answers **400 "The CSRF token is
  missing."** rather than 401, because the CSRF check runs first for anyone
  not signed in. Misleading in a log, harmless in a browser.
- `rollup` is empty after 20 seconds of streaming; it is written over time.
- bug-046 and bug-047 are fixed on the branch but **not yet on the running
  install** — it runs an image built before them.
