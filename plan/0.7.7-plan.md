# SQLDesk 0.7.7 — scope agreed with Iqbal, 2026-10-23

Two inputs. Iqbal's list: Mimir queries do not work, and MCP catalog
provenance and write-back (SD-1 to SD-15). And a code audit of the whole of
0.7.6 for bugs, reliability and size: seven areas (web tier, workers, query
runners, streams and uploads, MCP and catalog, frontend, image and chart),
each read end to end, the serious findings checked again by hand and the
image measured.

**Verified** means re-checked by hand: read again, run, or measured. Everything
else is from reading the code and says so in its line.

## Release shape — decided 2026-10-23

**Everything below is 0.7.7.** Iqbal chose one release over the split. Work
goes in this order, each step committed once verified: security, data loss,
Mimir, MCP provenance (SD), reliability, size, CI and frontend. Where a section
heading says 0.7.8 or 0.7.9 below, that was the proposed split; it now all
ships in 0.7.7.

## 1. Security — first, whatever the shape

- **S1. Stream SQL runs on an unsandboxed DuckDB — verified, high.**
  `kafka_stream.py:302` uses `duckdb.connect(":memory:")` with nothing locked
  down. It runs in the web process with view access only. Shown on DuckDB 1.5.6:
  it reads any file (in a pod, `/proc/self/environ` holds the secret key and
  the DB URL), lists the filesystem, and writes files. It could also open other
  organisations' windows and uploads, and install extensions. Fix: after
  attaching the windows, `allowed_directories`, `enable_external_access=false`,
  autoinstall and autoload off, `threads`, `memory_limit`, then
  `lock_configuration`. Add a test that `read_text('/etc/passwd')` is refused.
  Broken since 0803f241 (2 October).
- **S2. MCP's cost ceiling never applies — verified, high.** `cost.py`
  calls `.get("rows")` on a QueryResult model. The AttributeError is swallowed
  ("could not estimate"), so the query runs. The tests fake a dict and pass.
- **S3. "Read-only" sources that write, high.** MongoDB `$out` and `$merge`,
  and JSON/URL with `method: post`, skip every MCP check.
- **S4. MCP's 1000-row cap is easy to bypass, high.** It only applies to a
  plain leading SELECT: a WITH query, an explicit LIMIT, or any query on Athena
  or Presto gets the full result.
- **S5. The catalog's REST endpoints ignore data-source access, high.** A
  curator can list tables and columns of sources they cannot read, export the
  SQL of verified queries, and write descriptions that models are then fed.
- **S6. Subscription emails render as the owner, high.** Recipients receive
  widgets from data sources they cannot see. Slack sends do the same.
- **S7. Running streams lists every stream to every signed-in user,
  medium.** Topic names, columns and errors are exposed.
- **S8. The ClickHouse password goes into the URL and the logs, medium.**
- **S9. Dropped on review.** The audit read the HTTP drivers' plain
  `requests` calls (Prometheus/Mimir, ClickHouse, Elasticsearch...) as an SSRF
  bypass. Their URLs are set by an administrator on the data source, not by a
  person in a query, and the private-address block (on by default) would
  refuse exactly the internal addresses those engines live on -- every
  in-cluster Mimir and ClickHouse. The block guards the JSON and URL sources,
  whose queries name URLs, and they already use it.
- **S10. Restoring a query version skips the dropdown access check, low.**

## 2. Data loss and broken core flows — 0.7.7

- **B1. Deploys kill running queries after 6 seconds — verified.** On Linux
  the worker is RQ 1.16.1's HerokuWorker, whose `imminent_shutdown_delay` is 6.
  The 290 s grace period, the comments and the docs all say otherwise. A
  scheduled query counts it as a failure; the warehouse query keeps running.
  Stream consumers die mid-flush.
- **B2. Joining a running query gives 403 to everyone but its starter —
  verified.** Since 0.5.0 (e684a6c6). The second viewer of a dashboard sees
  "failed communicating with server".
- **B3. An upload is deleted without notice — verified.** `send_mail` swallows
  every error, so a failed warning counts as sent. Separately, a file already
  past expiry is warned and deleted in the same run.
- **B4. The admin Streams page edits the wrong topic.** It looks the stream up
  by cluster, not by topic, so pin and budgets change whichever row comes first.
- **B5. On a topic over the ceiling, the sample rate runs away.** Simulated:
  at twice the ceiling it stores about 64 events/s instead of 5,000, then
  collapses and repeats every few minutes.
- **B6. One message with a different type kills the stream consumer.** So
  does a JSON key containing `"`.
- **B7. A reader of the window can lock out the writer, which then dies.**
  A stream query attaches every topic on the cluster, not just those it names.
- **B8. Subscriptions resend every minute after any failure.** No backoff,
  and earlier recipients get it again.
- **B9. Smaller faults.**
  - Forking a streaming dashboard makes a saved one.
  - Verifying a dashboard or moving it to a folder gives its editor a 409.
  - A folder holding only archived dashboards cannot be deleted.
  - Unknown ids give 500 instead of 404 in about 15 places.
  - Mongo `Decimal128("0")` and empty pg ranges fail when the result is stored.
  - MySQL `ssl_mode` is ignored unless "Use SSL" is ticked.
  - BigQuery cancel raises AttributeError.
  - Presto loses its error message.
  - SQLite cancel crashes.
  - ClickHouse fails any query over 30 s and leaves it running.
- **B10. `compose.prod.yaml` enables Streams with nothing to consume them.**
  Jobs pile up in Redis.
- **B11. arm64 images offer SQL Server (ODBC) and Databricks, which cannot
  connect there.**
- **B12. Schema uploads hide the reason they failed — verified, ours (0.7.6).**
  The page shows axios's "Request failed with status code 400" instead of
  "x.proto:2: …"; the client never reads `response.data.message`. The same
  pattern runs through Manage Topics.
- **B13. Frontend bugs people will hit.**
  - "Restore version" silently throws away unsaved SQL.
  - Unapplied dashboard parameter edits vanish as each widget finishes loading.
  - Table sort and query filters reset on every new result, so they are
    unusable on a streaming query or a live dashboard.
  - One failed poll (a 502 during a deploy) marks a running query failed.
    Polling never stops on unmount and ignores hidden tabs.
  - The stream editor runs a full Execute every 2 s: an event row and a
    notification-permission request per tick, about 1,800 an hour per tab.
  - After a deploy, a chunk that failed to load stays broken until a reload,
    which wall screens never do. Any stray error anywhere blanks the whole app
    for good.
  - One failed poll unmounts the admin Overview and Running Queries pages,
    which are open exactly during incidents.

## 3. Mimir — every reason it fails (0.7.8)

- **M1. MCP refuses every PromQL query — verified.** `mimir` is missing from
  MCP's list of non-SQL languages (`prometheus` is on it), so PromQL is checked
  as SQL. The same gap affects yandex_* and google_search_console. Fix: a
  `query_language` attribute on each runner instead of a hand-kept list, and
  check_sql/explain_query refuse non-SQL properly.
- **M2. The editor mangles PromQL — verified.** `parse_qs` turns `+` into a
  space: `a + b` becomes `a   b` (a 400), and `web-[0-9]+` becomes
  `web-[0-9] `, which silently matches nothing. An `&` inside a label splits
  the query.
- **M3. Mimir's own error message is thrown away.** The user sees only "400
  Client Error".
- **M4. A wrong tenant reads as "query result is empty."** Shown as an error,
  while the connection test passes for any tenant because it runs `1`.
- **M5. Scalar, string and native-histogram results crash.** So does a range
  selector in an instant query.
- **M6. The `/prometheus` prefix cannot be set from the form.** Grafana Cloud's
  `/api/prom` 404s.
- **M7. Times are handled wrongly.**
  - `start=now-1h` crashes.
  - The timezone is dropped unless the worker runs in UTC.
  - start/end with no step silently runs as an instant query.
- **M8. Columns come from the first series only, and `value` is a string.**
- **M9. No HTTP timeout.**

## 4. MCP provenance and write-back — SD-1 to SD-15 (0.7.8)

What the code does today, which sizes each item:

- **SD-1 find_queries.** Returns name, a [VERIFIED] mark, "verified by/on —
  note", description, data source and updated date. It does **not** return the
  SQL, owner, last modifier, tags or draft flag (drafts are filtered out). No
  tool fetches SQL by id. The REST `/api/queries` already serializes owner,
  `last_modified_by`, `is_draft` and tags, so this is mostly exposing fields.
  Also: `find_queries` exists twice and the copies already differ (the eval
  scores the other one).
- **SD-2 find_measures.** Only approved measures are returned. States exist
  (proposed, approved, denied) and the Catalog page already has the curator
  queue with Approve and Deny. There are **no proposed_by or approved_by
  columns**: the reviewer is only in an Event row. Needs two columns.
- **SD-3 descriptions.** update_table writes `description` with
  `description_source = "mcp"`. There is no `described_by` or `described_at`.
  **Root cause of the reported bug:** find_context prints a card that is only
  rebuilt by the harvest (every 24 h, or never if the source is paused, the
  schedule is 0 or the harvest fails). expand_table prints no descriptions at
  all. Fix: rebuild the card on every write, and add descriptions to
  expand_table.
- **SD-4 find_dashboards.** Dashboards do have verification (0.7.3), but the
  tool never reads it or the owner. It also only searches the 200 most
  recently updated dashboards.
- **SD-5 null, not omitted.** Every tool returns plain text with no output
  schema. Lines are dropped or replaced with "none" and "?". Needs structured
  output (MCP `structuredContent`) with explicit nulls.
- **SD-6 to SD-9.** save_query, update_query, propose_measure, and authorship
  on update_table, as specified. Measures and the curator queue exist, so
  SD-8 is a write path into them.
- **SD-10 the catalog:write scope.** **API keys have no scopes today**: each
  user has exactly one key. OAuth tokens store a scope that nothing reads.
  Decision below.
- **SD-11 audit.** `mcp_events` exists (90 days) but records nothing about an
  update_table write: no table, no text. Add before and after, plus the 50 a
  day cap.
- **SD-12 no trust-granting tools.** Verify, approve and delete stay in the UI.
- **SD-13 Catalog UI.** A filter and badge for items made by agents.
- **SD-14 hidden.** Any curator's API key can hide a table today. Move it to
  the UI.
- **SD-15.** Same as M1.
- **Also in this part — retrieval quality.**
  - Natural questions match nothing: "revenue by region last quarter?" needs
    the literal `quarter?`.
  - Tables with the same name in two sources collide, and cards never say
    which source.
  - The harvest never drops renamed columns.
  - An import overwrites newer human descriptions.

Answers to the three open questions in the request:
1. **Owner and repo.** Iqbal Singh, `github.com/bot-netizen/sqldesk`.
2. **Does REST already return owner, last modifier and draft flag?** Yes. The
   single-query GET returns all three; the list returns `user`, `is_draft` and
   `last_modified_by_id` only.
3. **Is the SQL safe to hand to agents?** Recommend returning it under the
   same rule as the UI: only queries on a data source the caller can read.
   That widens nothing. SQL with credentials in it is a data problem the UI
   already has.

## 5. Reliability — 0.7.9

- **Time limits.** Default query time limits (300 s ad hoc, 1800 s
  scheduled), passed down as engine statement timeouts. Today it is -1: a hung
  query holds a worker for ever and passes every probe.
- **Row cap.** A global row cap with a "truncated" flag. Today every runner
  fetches everything.
- **Web tier.**
  - gunicorn `gthread`; today it is 4 sync workers, and MCP run_query, Test
    connection, Slack share and stream queries each hold one for up to 60 s.
  - Size the pool, turn pre-ping on, add a statement timeout and an
    idle-in-transaction timeout.
  - `preStop`.
- **Redis.**
  - Writes on every request become best effort; today a Redis blip turns every
    signed-in request into a 500.
  - Bundled Redis: resources, `maxmemory` with `noeviction`, `Recreate`.
  - Store data-source pause in Postgres; today it lives only in Redis and a
    restart un-pauses everything.
- **Queues and jobs.**
  - A separate worker for periodic, default and emails, so two slow queries
    cannot stop scheduling, alerts and mail.
  - Job retention: 10 minutes for live jobs; today it is 12 h.
  - Cap the scheduled-query backoff; today a day of outage delays a 5-minute
    query by 17 h.
  - Fix enqueue dedupe with a compare-and-delete lock.
- **Events.**
  - One job per event, any list length, about 75 per dashboard view (72,836
    rows in a month on one user).
  - Cap the list, write in one job, schedule the cleanup that exists but
    never runs.
  - Drop the widget and visualization view events.
- **Indexes.**
  - `queries(query_hash, data_source_id)`
  - `queries(latest_query_data_id)`
  - `query_results(retrieved_at)`
  - `changes(object_type, object_id, id)`
  - `events(created_at)`
  - Drop the duplicate query_results index.
- **Result write path.** Measured: 1.9 s of 2.3 s on 200k rows is a size walk
  for a log line and a deep copy.
- **Streams.**
  - A queued consumer is told apart from a quiet topic.
  - No duplicate consumer jobs.
  - Hand-overs survive a wait.
  - Each flush stops parsing three times and running about a dozen catalog
    queries.
- **Chart.**
  - PDB.
  - Scheduler with two replicas; rq-scheduler already locks.
  - Resource requests match measured use.
  - The renderer rolls when its token changes.

## 6. Size — 0.7.9 (measured on the published 0.7.6, 1.50 GB)

- **Multi-stage Dockerfile.** gcc, g++, git, perl, headers and sudo ship at
  runtime: about 250–300 MB.
- **Google API discovery documents.** 575 files, 3 used: 92 MB.
- **botocore data.** 355 services, about 6 used: about 70 MB.
- **Left-overs.** The uv binary 50 MB, test suites 70 MB, pip 13 MB, source
  maps 22 MB, docs and client sources about 20 MB.
- **GeoLite 2018 database, 55 MB.** It is reopened once per event row and is
  eight years stale. Drop it with the unused events GET.
- **The dependency layer is rebuilt every release** because uv.lock records
  the version. Every patch re-pulls about 300 MB compressed.
- **Lazy SDK imports.** Starting a process takes 3.6–5.3 s and goes from 43
  to 208 MB, mostly SDKs nobody uses. Saves about 165 MB per process — about
  a gigabyte across a small install — and around 3 s of start-up.
- **ibm-db** (44 MB) moves from the base install to `all_ds`.
- **Dead runners and dependencies.** Rockset (shut down 2024), Google
  Analytics v3, legacy Elasticsearch, memsql, sasl, oauth2client, nzalchemy.
- **Frontend.** First load is about 520 KB gzip.
  - **Production CSS is not minified — verified.** `app.css` is 39,426 lines
    with 266 comments, and there is no minimizer in the webpack config.
  - Three icon fonts for about 57 icons; Material Design Iconic is all of the
    render-blocking `6702.css`, for 14 icons.
  - All of Bootstrap 3, and 39 antd component styles loaded globally,
    including two nothing uses.
  - Full lodash alongside a modular copy; core-js 2 for 2017 browsers;
    8 needless moment locales; one 1 MB vendor chunk that every dependency
    bump invalidates.
  - About 60–90 KB gzip off the first load, at low risk.
  - Hashed assets are revalidated on every load, brotli-compressed per
    request, and carry a cookie, so no CDN will cache them.
  - `QueryResult.update()` still takes 0.4–0.8 s per 20k×8 result with
    several timestamp columns: it decides each cell's type instead of each
    column's.
  - Auto-height widgets measure the DOM every 200 ms, forever; a rotating
    wall re-renders the whole dashboard 4 times a second.

Together: about 1.5 GB down to 0.9–1.0 GB.

## Decisions

1. **Release shape: all in 0.7.7** (Iqbal, 2026-10-23).
2. **SD-10: scoped API keys.** A new `api_keys` table: several named keys per
   user, each with scopes. `users.api_key` stays as the read-only key, and
   OAuth tokens start honouring the scope they already store. Taken as the
   recommendation; Iqbal said go without choosing.
3. **The widget and visualization view events are dropped.** Also taken as the
   recommendation.

## Direction set 2026-10-24 (supersedes the release mechanics above)

- **No release is cut until every item here is done.** No rc tags, no
  version bump, no GitHub release. Changes are validated and pushed to
  `release/0.7` as they land. This is the release that goes public.
- **The name is SQLDesk.** The former name is out of code, settings and
  comments (commit 13a25ac4). What stays, and why: `LICENSE.redash` and
  `NOTICE` (BSD 2-Clause condition 1 on the inherited code), the attribution
  paragraph in README and the docs footer, the migrations that have already
  run, and `plan/`'s own history. The docs may say SQLDesk is built on top of
  Redash; they may not compare the two.
- **Docs are rewritten at the end, not patched.** Out: the comparison table,
  the competitive and performance argument in `docs/why.html`, the
  upstream-release claims in `docs/roadmap.html`. In: architecture, Kafka
  streams, MCP (collecting context, and what an admin can ask the agent to
  change), deployment and scale. Written for somebody who has never heard of
  the upstream project.
- **Scale and MCP context are first-class goals**, not a section: the
  reliability and size work below, plus every SD item that gets more real
  context into MCP (SQL, provenance, descriptions, authorship) and the write
  tools an admin or a permitted group can ask an agent to use
  (`save_query`, `update_query`, `propose_measure`, `update_table`, under the
  `catalog:write` scope with an audit trail and a daily cap).
- Local minikube deploy once the work is done, from a locally built image
  rather than a published tag.
