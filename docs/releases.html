What shipped, and when

SQLDesk is a fork of Redash that has been rebuilt one layer at a time. Each release has a theme, and the theme is the point — a release that does a little of everything is a release nobody can describe.

0.6 Building

AI at the core — not a chat box bolted to the side.

  • A context service built from harvested warehouse metadata and, as it accumulates, your own query history. Everything else is a client of it.
  • An MCP server, so Claude Desktop and the in-app assistant share one tool layer, one set of guards and one permission model.
  • An optimize button beside Execute. The first half is deterministic — parse, EXPLAIN, rule packs per engine — and needs no model at all.
  • A semantic layer whose definitions are proposed from what people already wrote, approved by an admin, and stored as Cube-native YAML you can keep in git.
  • Your choice of model: a hosted API, or something running on your own hardware. Configured from the CLI on the server.

0.5 Released

A dashboard that costs less to look at, and more room on it to say things.

  • One fetch for one result. A query behind five widgets was fetched and parsed five times; now one request serves all of them, shared only when they are genuinely asking for the same thing.
  • The chrome gave the charts their space back. 44px of widget header where there were 57, a title that says one name instead of repeating the query's, and filters in the header rather than a full-width band.
  • Textboxes became somewhere to write. Tables, fenced code, task lists and raw HTML through DOMPurify, a Write/Preview editor, and a tile you can switch off so a heading divides the page instead of sitting on it.
  • Eight more chart types, drawn by ECharts, with a matrix test that puts every visualization through every option it offers.
  • An Admin section that answers what is running, who is running it, and what is about to run out — with the ability to cancel a query and run cleanup now.
  • Alerts can carry a picture, rendered by a headless browser in its own optional container. The published image does not grow for people who never turn it on.
  • A twenty-four column grid, so a widget can take a third of the width, with a migration that brings existing dashboards across.

0.4 Released

Dashboards you watch rather than read.

  • Live dashboards. The server refreshes a dashboard every 30 seconds to 5 minutes, once for everyone looking, and only while somebody has it open.
  • The visualizations that go on a wall — a gauge, a stat with a sparkline and a target, progress and bullet bars, a status grid, table cells that colour and carry data bars, reference lines and bands.
  • Charts moved to Apache ECharts, which is what made the rest of it possible.
