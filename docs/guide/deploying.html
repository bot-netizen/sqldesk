Deploying

Five processes and two databases — see Architecture. Everything below is a way of arranging those.

What must be set

VariableWhy
SQLDESK_COOKIE_SECRETSigns sessions. The server refuses to start without it.
SQLDESK_SECRET_KEYEncrypts data source credentials. Changing it makes existing ones unreadable.
SQLDESK_DATABASE_URLSQLDesk's own Postgres, not your warehouse.
SQLDESK_REDIS_URLQueues and cache.
SQLDESK_HOSTThe address in emails and alert links.

Keep the two secrets somewhere they survive a redeployment. Losing the cookie secret logs everyone out; losing the secret key loses every stored credential.

Docker Compose

cp .env.example .env        # then fill in the two secrets
docker compose -f compose.prod.yaml up -d
docker compose -f compose.prod.yaml run --rm server manage database create_tables

Pin the image in .env as SQLDESK_IMAGE=. Without it the compose file falls back to a default that may be older than what you are running.

Upgrading

docker compose -f compose.prod.yaml run --rm server manage db upgrade

Run it after every image change, before the new server takes traffic. Release notes call out any migration that rewrites data rather than adding to it.

Kubernetes

A Helm chart is in charts/sqldesk. On minikube the server is exposed as a NodePort:

minikube start
helm install sqldesk ./charts/sqldesk \
  --set secrets.cookieSecret=$(openssl rand -hex 32) \
  --set secrets.secretKey=$(openssl rand -hex 32)
minikube service sqldesk

For a real cluster, put an Ingress in front and terminate TLS there — an API key travelling to /mcp over plain HTTP is a credential in the clear.

Scaling

  • Queries queueing — more workers.
  • Pages slow to load — more web workers. A different problem with a different fix.
  • The scheduler is one process. Two would double-schedule everything.
  • Give a slow data source its own queue so it cannot starve the others.

Backups

Back up Postgres. Redis holds queues, locks and a schema cache — losing it costs in-flight jobs and nothing else, which is why it can be a plain container with no persistence.
