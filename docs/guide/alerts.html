Alerts

An alert watches one query's result and tells you when it crosses a line.

How it works

An alert is checked after its query runs, not on a timer of its own. An alert on a query that is not scheduled only fires when somebody runs the query — which is the single most common surprise, and the fix is to give the query a schedule.

It reads one column of the first row, compares it, and is then either triggered or ok. Notifications are sent on the change between those states, not on every check, so a metric sitting above its threshold for a day is one message rather than a hundred.

Setting one up

  1. Write a query returning the number you care about. One row is easiest.
  2. New Alert, choose the query, the column, the comparison and the value.
  3. Add destinations — email, Slack, a webhook, and others.
  4. Optionally write a custom template for the message.

Rearm

How long before a still-triggered alert notifies again. Zero means it tells you once and stays quiet until it recovers and trips a second time.

Attachments

An alert can carry pictures of up to five dashboards or queries, rendered by a headless browser. It is off unless a renderer is configured, and the published image does not include one — it runs in its own optional container.
