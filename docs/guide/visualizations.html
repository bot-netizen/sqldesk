Visualizations

A visualization belongs to a query and draws its rows. One query can have many, and they all show the same data — so fixing the SQL fixes every one of them.

Choosing one

You want to showUse
Rows, as rowsTable — with per-column formatting, colouring and data bars
Something over timeLine, area, or a stat with a sparkline
Categories comparedBar or column; horizontal bars when the labels are long
One number that mattersCounter, or Gauge when there is a target or a healthy range
Parts of a wholePie for a handful of slices; a stacked bar for more
Progress toward a targetProgress bar, bullet bar, or Gauge
Status across many thingsStatus grid — one tile per row, coloured by a column
Two numbers relatedScatter, or a bubble chart with a third for size
Where something isMap (markers), or Choropleth for regions
Flow between stagesSankey, or Funnel for a conversion sequence
DistributionHistogram or box plot

Turning a point or a cell into a link

This is the drill-down: click a bar, land on the query, dashboard or system that explains it. It is configured per visualization, and the important part is that the link is built from the row — so one setting makes every point link somewhere different.

On a chart

Open the visualization editor and go to General. Tick Enable click events — until you do, the two settings under it stay greyed out and clicking a point does nothing:

Enable click events
Makes the points clickable. Nothing below works without it.
Open in new tab
Usually what you want from a dashboard somebody is watching.
URL template
A URL with placeholders filled in from the point that was clicked, for example /dashboards/12?p_region={{ @@x }}. The braces are part of it.

The placeholders are:

  • {{ @@x }} and {{ @@y }} — the point you clicked;
  • {{ @@name }} — the name of the series it belongs to;
  • {{ @@x1 }}, {{ @@y1 }}, {{ @@x2 }}, {{ @@y2 }} … — every series at that same position, numbered in the order they appear under Series. Use these when the link needs the whole row rather than the one line under the pointer.

Values go in raw, not formatted: a tooltip may read 1.2k, but the URL gets 1200, because the other end has to be able to look it up. A placeholder that matches nothing is replaced with an empty string rather than left in the URL.

A worked example. A column chart of revenue by region, where clicking a column opens a dashboard filtered to that region:

Enable click events:  yes
Open in new tab:      yes
URL template:         /dashboards/7-regional-detail?p_region={{ @@x }}

Because {{ @@x }} is filled in per point, the North column links to North's dashboard and the South column to South's. There is no per-point configuration.

Charts have no link text setting — the whole point is clickable, and there is no label to write. Per-cell link text is a table thing, below.

On a table

A table column can be a link instead of text. In the visualization editor choose the column, set its Display as to Link, and fill in:

  • URL template — https://tickets.internal/{{ id }}, where id is any column in the row, named exactly as it appears in the result;
  • Text template — what the cell shows, for example #{{ id }}. Leave it empty and the cell shows the URL;
  • Title template — the hover text;
  • Open in new tab.

Note the difference from a chart: a table's placeholders are column names, with no @@ in front of them. That prefix belongs to charts, where there are no column names to use. {{ @ }} is the one shorthand here — the value of the column being displayed.

Any column of the row can be used, not only the one being displayed. A common shape is to select an id you never show, and use it to build links in the column you do.

If the link does not appear

  • The placeholder has to match exactly, including case: a column name on a table, @@x and friends on a chart.
  • On a chart, Enable click events has to be ticked. Without it the URL template is greyed out and clicking does nothing.
  • A relative URL (/dashboards/7) stays inside SQLDesk. An external one needs its scheme — https:// — or the browser treats it as relative.
  • On a table, a URL template that resolves to nothing leaves the cell empty rather than showing a broken link.

Formatting numbers

Every numeric column and most chart values take a format string. It is applied in the browser, so it changes what is shown and never what was fetched.

Format1234567.891 becomes
0,01,234,568
0,0.001,234,567.89
0.0a1.2m
$0,0.00$1,234,567.89
0.00%applied to 0.1234 gives 12.34%
0[.]00decimals only when there are any

Thousands and decimal separators follow the organization's setting, so the same format string reads correctly for everyone.

Colouring by the value itself

A series colour says which measure a bar is. It cannot say whether the number is any good, and on a chart of variances that is the only thing anybody wants from it.

Bars on a chart

In the visualization editor, Colors → Color bars by value. Set a breakpoint and a colour for bars below it; optionally a second colour for the rest. The common setting is a breakpoint of 0 with one colour below it — negatives in red, everything else as it was.

A bar exactly at the breakpoint counts as above it, so a breakpoint of zero colours negatives and leaves a zero bar alone: it has no height to colour, and reading it as a shortfall would be wrong.

Bars only. A threshold on a line would colour its markers and leave the line itself one colour, which says less than the goal lines under Lines & Zoom — use those instead.

Telling two lines apart

Under Series, a line or area series has a Line setting: solid, dashed, dotted, fine dots, long dash or dash-dot. Use it when two series are the same measure at different times — this week against the same hour last week. Giving the comparison its own colour says it is a different thing; giving it its own pattern says it is the same thing, earlier, which is usually what the reader needs. The picker draws each pattern rather than naming it.

Bars inside table cells

On a number column, Data bar behind the number draws each value as a bar across its cell, scaled against the largest magnitude in the column. Two colours sit below it: the bar's colour, and the colour it takes below zero.

Which way a bar points depends on the column, not on a setting:

The column holdsThe bars
Only values at or above zeroGrow from the left edge, using the full width
Only values at or below zeroGrow from the right edge — the mirror of it
Values on both sidesZero sits in the middle, with a line drawn on it, and the sign is the direction

A shared zero is only worth the width it costs when there is something on both sides of it, which is why an all-positive column still gets the whole cell.

Four more settings decide how it looks:

SettingWhat it does
BarSolid paints the colour as chosen and restates the number over the bar in whichever of black or white can be read on it. Tinted is the older, paler wash — readable behind text, but a weak mark on its own.
Column widthA floor for the column, because a table sizes a column to its widest number and a bar in that much space says nothing.
Show the number on the barTurn it off to read the column as shapes. The number stays in the page for anyone using a screen reader.
Fill (under Colour the → Cell background)The same choice for a coloured cell: tinted keeps the text dark, solid paints the cell and flips the text to suit.

Stacked panels: several plots, one clock

Spend reads around 1,400, a percent change around 20 and a rate around 5. There is no single y axis on which all three can be read — put them together and two of them are flat lines along the bottom. A second y axis handles two scales; a third needs a second plot.

Under Y Axis → Panels, choose up to four. Each series then picks its panel on the Series tab. The panels share one x axis, one legend and one cursor: hovering a moment in the top panel marks the same moment in the others, which is the whole reason to stack them rather than put three charts side by side.

Use it when the series are different measures against the same clock. For the same measure broken down different ways — revenue by region, by channel, by product — the categories differ, so stacking is wrong and buttons on a dashboard widget are right.

Panels are for upright charts. A pie has no grid to divide, a heatmap builds its own, a box plot is a distribution per category, and a sideways bar chart already runs its categories down the axis the panels would cut — each of those draws as one plot whatever is set.

A chart too short to divide still draws every panel it was told to, rather than quietly collapsing to one. A taller widget is the fix, and a chart that ignored the setting would never tell you that.

When several rows share an x

A query keyed on more columns than the chart plots returns several rows per point. Keyed on region, channel and product but plotting region alone, every region arrives several times, and something has to happen to the repeats.

Something always did: they were added up, silently. That is right for money and wrong for a rate — the average of four conversion rates is a conversion rate, their sum is nothing at all.

Under General → When rows share an x:

SettingUse it for
Add them upTotals, revenue, counts of things. The default, and what every chart saved before this did.
Average themRates and ratios, where a total means nothing.
Keep the lowest / highestThe worst or best case at each point.
Count the rowsHow many rows share this x, ignoring the measure.

Two details worth knowing. An average divides by the rows that carried a number, not by the rows — counting the empty ones would read every missing reading as a zero. And a point with no readings at all is drawn as a gap rather than a zero, because zero is a claim about the measure. Counting rows is the exception: an order with no total is still an order.

Offered on column, line and area charts. A scatter or bubble chart is a point cloud and keeps every row, so collapsing it would be the bug rather than the feature.

Dates and times

Times are stored as the warehouse returned them and displayed in the organization's configured format. If a chart's x axis looks wrong by exactly some number of hours, the column is almost certainly a timestamp without a time zone — the fix belongs in the SQL, where the intent is known.
