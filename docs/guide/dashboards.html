Dashboards and textboxes

A dashboard is a grid of widgets — visualizations from any number of queries, plus textboxes for the words that explain them.

Arranging

Press Edit to move and resize. The grid is twenty-four columns wide, so a widget can take a third of the width as easily as a half. Nothing is saved until you press Done Editing — moving a widget and navigating away changes nothing, deliberately.

Filters and parameters

Two different things that look alike on screen:

Dashboard-level parameters
A query parameter mapped to the dashboard rather than the widget. Changing it re-runs every query mapped to it. Use this when the warehouse should do different work.
Dashboard filters
Switched on per dashboard, driven by naming a column something::filter in the SELECT. They narrow rows already fetched, in the browser, without re-running anything.

Both live in one button beside Refresh, with a count. While you are editing the layout they move into a row of their own, because that is where they can be dragged into order.

A widget can also keep its own parameter, on its title row. Two visualizations of the same query each keep their own value — so you can show North and South side by side — and they share a single fetch whenever their values agree.

Textboxes

Add one from Edit → Add Textbox. A textbox has three settings: the text, a style, and an alignment.

Style Plain removes the tile — no white card, no border — which is what you want for a heading dividing a page. A section heading sitting in a card reads as a widget that failed to load. Style Card is the ordinary widget look.

What markdown is allowed

Standard markdown with GitHub extensions, plus raw HTML. The editor has Write and Preview tabs, and the preview carries the style and alignment you chose, so it shows the widget rather than an impression of it.

Raw HTML

Allowed, and sanitised on the way in. This is how you get two columns, a coloured callout, or an image at a chosen width:

<div style="display:flex;gap:14px">
  <div style="flex:1;padding:10px;background:#e4f4f7;border-radius:6px">
    Left
  </div>
  <div style="flex:1;padding:10px;background:#f7eedd;border-radius:6px">
    Right
  </div>
</div>

style and class survive. <script> does not, and neither does an onerror or any other event handler — every string is sanitised before it reaches the page, whoever wrote it.

Sharing

A dashboard can be given a public link that needs no login. Anyone with the URL sees it, so it is a secret-by-obscurity share rather than a permission — treat the link as the credential. Public links can be disabled for the whole instance in settings.

On a wall

A dashboard can be made live: the server refreshes it every 30 seconds to 5 minutes, once for everyone looking, and only while somebody has it open. /wall/dashboards/<token> gives a version with no chrome, for a screen nobody interacts with.
