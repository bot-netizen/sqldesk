Design

How the AI features actually work

What happens between your question and your results, what is sent where, and what stops a confident wrong answer reaching you. Nothing here is magic, and none of it runs until you configure a model.

Asking a question

The assistant never sees your whole warehouse. It asks the context service for the handful of tables that look relevant, drafts SQL, and has that SQL checked before anything runs.

Two rules that do not bend. Every identifier in generated SQL is checked against the catalog after parsing, so a column that does not exist fails here rather than at your warehouse. And every assumption is written down — “filtered to status='completed', because 90% of past queries on this table do” — because an unstated assumption is how you get a number that is wrong in a way nobody notices.

What is actually sent to the model

Not your data. Not your whole schema. A budget, assembled per request.

LayerWhat it holdsRoughly
Always onConventions, glossary, table names with a line of purpose each2–4k tokens, cached between requests
Retrieved5–10 candidate tables, columns already pruned to the ones people use3–6k
Examples2–3 similar queries somebody on your team already wrote1–2k
On demandFull column detail, only when the model asks for a specific tablevaries

Row values are not included, with one deliberate exception: the distinct values of low-cardinality columns like status. Without them a model writes status = 'complete', the query succeeds, and returns nothing — the worst failure mode there is. Columns you tag as sensitive are excluded from that, and a data source with AI switched off contributes nothing at all.

Optimizing a query

Two stages, and the order is the design. The first needs no model.

Stage 1 alone catches the things that actually cost money — a missing partition predicate, an implicit cast on a join key, SELECT * across a wide columnar table — and it will tell you the same thing every time, because it is rules rather than a model.

A rewrite you cannot defend is not shown. Both queries are normalized, explained, and run against a sample partition; row counts and a sorted hash of the results are compared. If they do not match, you are told so rather than handed a query that returns different numbers. Accepting a rewrite creates a new version of the query, with its lineage back to the original.

Where the semantic layer comes from

From the queries your team already wrote, and never without somebody agreeing.

Approved definitions are written in Cube's own format, so they are reviewable as a pull request and can be absorbed by Cube with no conversion. SQLDesk's own compiler reads the same files, so you do not have to run Cube to use them.

Once a metric exists, the assistant stops writing the aggregation at all — it picks a metric and the compiler produces the SQL. That removes the largest class of mistake in text-to-SQL in one move: the right tables, the wrong SUM.

Choosing a model

From the CLI on the server. Hosted or local, and nothing is on until you say so.

# a hosted API
sqldesk ai configure --provider anthropic --model claude-sonnet-5 --api-key-stdin
sqldesk ai configure --provider openai --model gpt-4.1 --api-key-stdin

# anything that speaks the OpenAI API, on your own hardware
sqldesk ai configure --provider local --base-url http://ollama:11434/v1 --model llama3.1

# what is configured, and whether it answers
sqldesk ai status
sqldesk ai test "how many orders were placed yesterday?"

Off by default

No provider configured means no AI surfaces, no tools registered and no outbound requests. The feature has to be turned on, not turned off.

Per data source

A warehouse can be excluded entirely, so its schema and value samples never leave the building even while another source uses a hosted model.

Keys on the server

Read from stdin or the environment, stored encrypted alongside data source credentials, never sent to the browser and never written to a log.

A budget you set

AI-issued queries get their own queue and a bytes-scanned ceiling, and anything expensive asks first. A generated query can scan a petabyte.
